# lark-bug-sync 设计文档

- 日期:2026-08-14
- 状态:已批准,待实现
- Skill 目录:`skills/lark-bug-sync/`

## 问题

bug 清单在 Lark 电子表格里,代码改动在 GitHub PR 里,两边靠人脑对齐:

- 修 bug 时要手动翻表找需求细节,表里写不下的复现步骤散落在 Lark 群聊里
- 改完要手动回表改状态,容易漏改或改错行
- 从表里看不出某个 bug 到底有没有人在改、改到哪一步

## 目标

一个 skill,让「查 bug → 修 → 关联 PR → 回写状态」这条链闭合,且**不牺牲团队共用表的安全性**。

非目标(本轮明确不做):

- 不从聊天新建 bug 行(往共用表新增行风险高)
- 不往群里回报修复结果
- 不改表结构(不加列)

## 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 关联方向 | **单向** —— PR 里引用 bug 序号,skill 反向扫 PR | 用户决定;表里不加 PR 列,零结构改动 |
| 引用格式 | **`XMFUN-<序号>`** | 表 A 列是纯数字。若约定 `#12`,GitHub 会解析成 issue/PR #12 链接,既误关联又制造大量假阳性。`XMFUN-12` 在 GitHub 无特殊语义 |
| 翻状态门禁 | **PR 已 merged** | 用户决定。避免「PR 开了但被关掉/打回」却已标待验证 |
| 目标状态 | 仅 `待解决` / `重新打开` → **`待验证`** | 见下「写操作边界」 |
| 表内写入范围 | **仅 G 列单格** | 不加列、不改结构、不动透视表 |
| 行定位方式 | **按 A 列值查找** | 序号看似 `行号-1`,但删行/插行即错位。算术推导会改错别人的 bug |
| CSV 解析 | **RFC-4180 正规解析(python3)** | 问题描述含中英文逗号混用,裸按逗号切会串列(实测已复现串到状态列) |
| 关联仓库范围 | 全部 `xiami-*` 仓(约 10 个) | 用户决定 |
| 聊天用途 | **仅只读**:按 bug 描述搜群聊讨论当上下文 | 用户决定;不新建行、不回报 |

## 写操作边界(核心安全设计)

这是一张**团队共用**表,写入必须保守。三重保护:

### 1. 只写一个方向

允许:`待解决` → `待验证`、`重新打开` → `待验证`。

**永不写 `验证通过`。** 那是测试的判断;开发代写等于绕过验证环节。这条硬编码为禁止项,不提供开关。

### 2. 其他状态一律不碰

`暂不处理` / `二期处理` / `UI设计` / `产品设计` / `无法复现` / `已上线` / `验证通过` → 跳过,列入报告让用户人工决定。空状态同样跳过。

### 3. 防覆盖同事改动

写前**重读该单元格**;若当前值 ≠ dry-run 时读到的旧值(说明期间有人改过),跳过该格并报告,不覆盖。

### 默认 dry-run

默认只列出计划改动(行号 / 序号 / 旧值 → 新值 / 依据的 PR 链接),**必须用户确认后**才真写。`--apply` 显式开启写入。

## 流程

| 步骤 | 做什么 |
|---|---|
| 0 预检 | 解析 wiki 链接 → 断言 `obj_type == "sheet"`;确认 lark-cli 认证与 scope;确认 `gh` 可用 |
| 1 查 bug | 读表 → 按经办人 / 状态 / 版本 / 类型筛选 → 输出清单 |
| 2 看详情 | 单个 bug 全字段 + 从 Lark 群搜相关讨论(只读)补充复现步骤等表里写不下的信息 |
| 3 扫 PR | 遍历 `xiami-*` 仓,找标题/body 含 `XMFUN-<序号>` 且状态为 merged 的 PR |
| 4 dry-run | 交叉比对,列出计划改动 |
| 5 确认后写 | 逐格写入,每格带冲突检查 |

## 测试策略

`tests/run.sh` 全离线、零网络 —— 用假 CSV 与假 `gh` 输出做夹具:

- CSV 解析:描述含中英文逗号、含引号、含换行时不串列
- 行定位:序号与行号不对应时(模拟删行)仍定位正确;序号不存在时明确报错
- 状态门禁:`待解决`/`重新打开` 允许;其余 7 种状态一律跳过;**断言任何输入都不会产出 `验证通过`**
- 门禁条件:PR 未 merged(open / closed)不触发翻状态
- 引用解析:`XMFUN-12` 命中;`#12`、`XMFUN-120`(前缀相同的更长数字)不误命中
- 冲突检查:旧值被改动时跳过而非覆盖
- dry-run 默认不写:断言无 `--apply` 时不产生任何写请求
- 依赖缺失(lark-cli / gh 未安装)时优雅降级报错,不崩

另需过 `skill-doctor` lint 与 `check-readme-sync.sh`(同步 `README.md` 与 `README.zh-CN.md`)。
